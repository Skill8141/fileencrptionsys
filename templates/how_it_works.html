5 · PBKDF2 deeply explained

Password + Random Salt ↓ PBKDF2 ↓ HMAC-SHA256 ↓ 600,000 iterations ↓ 256-bit Derived Key

PBKDF2 = Password-Based Key Derivation Function 2. It takes a password and salt, then applies HMAC-SHA256 hundreds of thousands of times to produce a strong key. It does not encrypt the password – it derives a key.

Why not SHA-256(password)? SHA-256 is too fast, making brute-force easy. PBKDF2 with many iterations makes each guess expensive.

🔁 Interactive metaphor: 1 / 600,000 iterations … each iteration mixes the password+salt again.

PBKDF2 is deliberately slow. 600,000 iterations ≈ 0.3s on a modern CPU. This makes brute-force impractical.

6 · Salt explained

Password = hello123 Encryption 1 Salt = ABC123 ↓ Key A Encryption 2 Salt = XYZ789 ↓ Key B

Same password + different salt ⇒ completely different key. Salt is random, stored with the ciphertext (not secret).

🧂

Why? Prevents identical passwords from producing the same key (rainbow tables). It's safe to store salt publicly.

7 · Nonce explained

KEY + NONCE + PLAINTEXT ↓ AES-GCM ↓ CIPHERTEXT

Nonce = number used once. AES-GCM requires a unique nonce per encryption. This project generates a random 12-byte nonce. Reusing a nonce with the same key breaks security. Nonce is stored with ciphertext, not secret.

8 · AES-256-GCM explained

┌─────────────┐ Plaintext ──►│ │ Key ────────►│ AES-256-GCM │──► Ciphertext Nonce ──────►│ │──► Authentication Tag └─────────────┘

AES: Advanced Encryption Standard. 256: key size in bits. GCM: Galois/Counter Mode, which adds authentication. Authenticated encryption ensures both secrecy and integrity.

Why better than plain AES? Plain AES doesn't detect tampering. GCM gives us an authentication tag that verifies the data hasn't changed.

8.5 · The AES algorithm — step by step

AES (Advanced Encryption Standard) is a symmetric block cipher. That means the same key is used to encrypt and decrypt. It processes data in 128-bit blocks (16 bytes) at a time.

What does "256" mean?

AES-256 uses a 256-bit key (32 bytes). The key size determines the number of rounds AES performs. AES-256 uses 14 rounds of transformation. AES-128 uses 10 rounds, AES-192 uses 12 rounds. More rounds = stronger security but slightly slower.

The four operations inside each AES round

SubBytes Byte substitution (S-Box)
ShiftRows Row shifting
MixColumns Column mixing
AddRoundKey XOR with round key

Each round applies these four operations to a 4×4 matrix of bytes called the state. The final round skips MixColumns. AES-256 repeats this 14 times, each time with a different round key derived from the original 256-bit key.

How does AES fit into our project?

Plaintext (file bytes) ↓ Split into 128-bit blocks ↓ AES-256-GCM encryption ┌─────────────────────────┐ │ Round 1: SubBytes │ │ ShiftRows │ │ MixColumns │ │ AddRoundKey │ │ ... repeat 14 times ...│ │ Round 14: SubBytes │ │ ShiftRows │ │ AddRoundKey │ └─────────────────────────┘ ↓ Ciphertext + Authentication Tag

What if we removed AES? There would be no confidentiality — anyone could read the file. AES is the core encryption engine of the project. GCM mode wraps around AES to add authentication.

Simplified explanation: real AES uses complex S-Box tables and Galois field multiplication. This visualization captures the spirit, not the exact math.

9 · Authentication tag

Original encrypted data ↓ Authentication Tag ↓ Valid ✅
Modified encrypted data ↓ Authentication verification ↓ FAILED ❌

Think of the authentication tag as a tamper-evident seal. If any byte changes, the tag verification fails and decryption is rejected.

12 · Wrong password

Encrypted File + Wrong Password ↓ PBKDF2 ↓ Wrong Key ↓ AES-GCM Authentication ↓ FAILED ❌

The derived key is different, so the authentication tag doesn't match. The application refuses to decrypt.

Salt and nonce are stored in plaintext — that's safe. Base64 is used to represent binary data as text inside JSON.

15 · Why Base64?

Binary Data ↓ Base64 ↓ Text representation

Base64 is NOT encryption. It just encodes bytes into printable characters (A–Z, a–z, 0–9, +, /). JSON cannot hold raw binary, so we use Base64 to store ciphertext, salt, nonce, and tag.

Example: bytes [0x48, 0x65, 0x6c] → Base64 "SGVs"
